# UART 控制 LED：从 RTL 到硬件运行

电脑发送 8N1 串口字节：`0x31`（字符1）开灯，`0x30`（字符0）关灯，其他字节保持。复位关灯。停止位错误不产生有效命令。设计没有发送回包、FIFO或硬件流控；连续命令应遵守接收器支持的位速率。

## 文件与接口

- `rtl/uart_led_top.v`：顶层；clk是板载输入时钟，reset_button_n低有效，uart_rx_pin输入，led_pin输出。
- `rtl/uart_rx.v`：两级输入同步，8N1单点采样接收；整数CLKS_PER_BIT>=8。
- `rtl/command_led.v`：只在valid有效时处理命令。
- `tb/tb_uart_led.sv`：自检，包含合法命令、非法字节、停止位错误、复位及超时。

顶层默认50MHz/115200baud，整数位周期434，实际波特率约115207。实际板上应根据原理图设置CLOCK_HZ，计算波特率误差，并确认LED极性。TB使用50MHz/6.25Mbaud加速，8个周期一位；仿真与RTL参数相互一致，不能把这组TB参数直接当作板测条件。

## 无开发板路线

1. 先画出 RX引脚→同步器→接收状态机→data/valid→命令寄存器→LED 的连接。
2. 有Icarus Verilog时运行`sh run-sim.sh`。通过后，改错命令解码并确认TB失败；恢复源码。
3. 有Yosys时运行`mkdir -p work`，再运行`yosys -s synth.ys`。得到通用网表与统计；它不是具体器件的实现结果，不能据此宣布频率或板级验收通过。
4. 对照TB，记录合法字节在哪一个沿让valid有效、命令寄存器在哪一个沿读取旧valid。
5. 没安装工具的项目必须记为“未执行”，不要将阅读示例当作仿真通过。

## 真实开发板路线

在前述仿真基础上继续：

1. 选择**实际器件**并新建工程，RTL三个文件作设计源，TB单列仿真源。综合顶层uart_led_top，仿真顶层tb_uart_led。
2. 核对时钟、复位按钮、LED、串口RX引脚。按原理图核对I/O电压和电平兼容，接好公共地；串口TX接FPGA RX。不要把RS-232电平直接接普通FPGA I/O。
3. 设置CLOCK_HZ、BAUD和LED_ACTIVE_LOW。按工具适配填写时钟与引脚约束；本包不提供任何开发板的猜测引脚。
4. 综合：检查顶层端口、未驱动、多驱动、锁存器、状态机和寄存器，保存资源报告。
5. 实现：完成布局布线、DRC、时序分析；检查未约束时钟/路径和setup/hold。异步输入的例外应以同步器及本器件方法为依据，不能全局false-path掩盖路径。
6. 生成配置文件。确认下载器、器件型号、配置方式一致，下载后先测复位和时钟，再发字符1/0及无效字符。
7. 不亮时按引脚/极性→复位→时钟→RX电平/位宽→valid→命令输出顺序定位。逻辑分析IP依厂商不同，不是便携RTL的一部分。
8. 断电重启区分临时配置与非易失启动，保存所用文件的哈希、工具版本和板卡版本。
9. 别人在干净目录中重新构建、运行自检并按同一条件板测，才完成复现。

## 工具适配与验证范围

- Vivado 2024.1（AMD）：XDC引脚/时钟约束，综合→opt/place/route→时序/DRC→write_bitstream。板级调试可用ILA。
- Quartus Pro25.1（Intel/Altera）：QPF/QSF工程与引脚、SDC时序，Analysis & Synthesis→Fitter→Timing Analyzer→Assembler→Programmer。Standard版本界面/器件不同。调试可用Signal Tap。
- Efinity2026.1.132（Efinix）：按该版本GUI和器件资料建立工程，Interface Designer连接物理接口，再按本版本时序指南配置时钟/约束，综合、P&R、分析和配置。不要套用XDC属性或未经核对的命令。

详细适配和厂商文档链接见课程页面。以上商业工具与真实开发板流程未在本次环境执行；本包提供可移植RTL及流程，不提供已通过的实现/板测报告。

## 交付报告

写清需求、模块/接口、复位行为、参数、工具版本、运行命令、预期与实际输出、负向测试、资源和时序、板测条件、已知限制。仿真、通用综合、器件实现、下载和板测分别记录，不相互替代。

同步寄存器上的ASYNC_REG属性是AMD工具提示，不是Verilog功能语义；在Quartus/Efinity中按对应版本的同步链识别与物理约束方法设置，不能假设该属性自动生效。
